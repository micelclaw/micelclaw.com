1/ Our MCP tool catalogue was 508,782 bytes. ~133k tokens of that were the descriptions of TWO fields, repeated across 409 tools — fields the model never fills in, because a host-side hook injects them. 🧵

2/ Emptied those two .describe() calls. Moved a 211-char boilerplate paragraph out of 408 tool descriptions and into the system prompt, once. Result: 278,533 bytes. −45.3%, zero capability lost. The entire change is deletion.

3/ Gotcha worth knowing: the fields stay DECLARED. The MCP SDK parses args in strip mode, so an undeclared field is discarded before the handler sees it — remove them from the schema and host-side injection writes into a void. Everything stops authenticating at once.

4/ Retraction #1: I claimed 408 tools were leaking into the model's context. They weren't — it received ~65. My bytes÷3.6 estimate was impossible (dense JSON is ~1.3 chars/token). The exact array is in the trace: context.compiled.data.tools. I estimated something I could have read.

5/ Retraction #2: I filed a "phantom retry" bug because usage.input kept coming in at 2× the previous call. It's the normal shape of a tool turn (call 1 emits the tool call, call 2 reads the result). Correlation: ratio≈2.0 ⇔ tool call, 11/11.

6/ That reframe is better than the bug: every prompt token is prefilled twice on a tool turn, and the local runtime doesn't reuse its KV cache between them. So the 45% cut is worth double.
