1/ We made a language model retype its own 64-hex auth token on every tool call. It worked — until it improvised a tool it hadn't been shown, and improvised the token too. 🧵

2/ Worse: subagents spawned via sessions_spawn passed through neither bridge that injected the token. They got nothing. Delegated tasks failed silently — our "Dalí doesn't answer" bug.

3/ The trap: a strong model copies the secret 6/6 on rails, so the design looks fine. Then one wrong turn later it emits a 42-char string that matches nothing — and subagents get it wrong 100% of the time.

4/ Fix: a native before_tool_call hook. For any claw-os__ tool it looks up the caller by ctx.agentId in an on-disk token map and overwrites auth_token host-side. No entry → it leaves the call untouched.

5/ The model never sees, types, or hallucinates the token. Subagents get their OWN token + their OWN scopes injected. Deterministic identity, keyed on who is actually running the tool.

6/ Full write-up — the hook, the atomic map write, the gotchas: https://micelclaw.com/blog/agent-identity
