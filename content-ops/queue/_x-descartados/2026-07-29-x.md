1/ We gave every user seven AI agents: one coordinator, six specialists, flat topology, per-user workspaces. That shape has held for four months without a single revision. Every hard bug was somewhere else. 🧵

2/ The coordinator kept delegating tasks to itself. Cause: the spawn tool declares agentId as Type.Optional(Type.String()) — optional AND with no description. The model fills in every parameter that was explained and omits the one that wasn't. Optional → the runtime spawns you.

3/ Sibling failure: a child spawned to do voice work inherits the PARENT's tools, not the target agent's. So "spawn a Dali" produces something named Dali without the audio tool. Two operations that differ only in whose capabilities they carry — the model will pick wrong.

4/ Then: parents yielding forever when a restart ate the child's announce-back (fixed with an 8KB tail-read detector + a 3-minute grace window), and child conversations invisible to the dashboard — so "refused", "never asked" and "answer got lost" all looked identical.

5/ Best one: we built a full DelegationPolicy — storage, per-agent defaults, retry with backoff, circuit breaker. All working. All unreachable: delegation is a native LLM tool inside the runtime, not an RPC we can intercept. Reverted the same day.

6/ Lesson I'd keep: find the insertion point BEFORE writing the policy. And treat tool schemas as prompts — two of the six failures were the model correctly following an under-specified contract.
